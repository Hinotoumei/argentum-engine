# Ordinary-action target chooser

The in-app browser rejects window.prompt, preventing real casting of a target-taking spell. Ordinary advertised action targets now use an on-page HTML dialog with server-provided eligible IDs, readable card/zone/owner labels, explicit selection, count validation, confirm and cancel. A stale session or interaction epoch prevents submission after asynchronous selection. Browsers without HTML-dialog support retain the existing prompt fallback.

Validation: 37 Node action-control tests pass (zero failures/skips), including rejecting a target submission when its session is replaced. Their DOM stub exercises the fallback and payload logic. Actual HTML-dialog acceptance was performed in the in-app browser against the local native jar: Persist offered only the nonlegendary creature in a graveyard also containing Ragavan and Think Twice; cancellation left the spell in hand and the stack empty; a real cast returned Grizzly Bears as 1/1 with one minus-one counter. The doubled case returned Hill Giant as 1/1 with two counters under Doubling Season. The lethal case left Llanowar Elves off the battlefield and increased the graveyard from three to four cards. These Persist acceptance fixtures used native work still awaiting full regression/publication, not a deployed server.

Scope: modal choices, X, combat pickers, and pending-decision prompts remain separate acceptance work. This change does not claim those browser paths are repaired. No production deployment was performed. The acceptance server startup 502 and a test-mirror listener left after a shell restart were diagnosed and recovered; no claim of an error-free browser console is made. Logs: work/tooling/persist-provider-control-tests.log and persist-full-build.log. Screenshots were displayed inline during acceptance; no local screenshot artifact was saved.
