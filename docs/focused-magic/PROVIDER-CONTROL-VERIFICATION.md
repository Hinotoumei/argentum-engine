# Focused Magic modal and paid-life controls

October 1. Control and display changes verified with the real local native server and normal browser controls.

The thin adapter now collects provider-advertised targets during choose-N mode selection, submits ordinal `modeTargetsOrdered` groups including empty groups, and supplies the flat target list expected by cast validation. Both the human and bot paths handle repeated modes. The existing stack-zone DTO supports converting stack card IDs to spell targets; no zone is inferred from a card name. Target distinctness follows the provider metadata and the native validator's flattened requirement order.

The native server also supports deferring modal target selection to a pending decision when a cast submits modes with no targets. Therefore the old adapter's absent cast-time target groups are not proof that all modal casts failed. The new checks pin the explicit submission flow; baseline failures describe missing behavior under that new contract, not observed live rejection of the legacy deferred path.

Pay-X-life casts now use a bounded integer chooser and submit `additionalCostPayment.payXLifeAmount`, preserving zero. Invalid and cancelled values submit nothing; the chooser does not silently clamp them or substitute a mana-X field. The adapter bot follows the existing zero policy. This is a legal payload policy, not evidence of strong Toxic Deluge AI strategy. Generic resource-heavy costs remain manual. Replicate counts already travel in server-enumerated action templates and survive cloning; no new repeat-cost field was required.

The Node VM checks execute the actual private button handler and bot materializer with provider-shaped data, stubbed dialogs, and a captured submission sink. They establish payload construction and cancellation, not engine behavior or live server acceptance. The earlier nineteen-case baseline had four passes and fifteen failures; all nineteen passed after the new flow. A twentieth test covers the human repeated-mode path. Four additional checks pin provider-projected power/toughness, chosen-X badges including zero, and provider stack text. All 24 checks pass.

The tabletop reads the provider's projected values rather than calculating stats or X locally. Fresh authoritative state clears the selected-card action panel, preventing an obsolete Cast button from remaining after a spell leaves the hand. The player's life header is above the battlefield; scrollable player sections keep it from being clipped behind the card row.

Two Chrome browser scenarios passed against the verified native server bound to localhost, with no browser page errors. Toxic Deluge was cast through the actual card action button and life-payment prompt: payment 2, stack badge X=2, caster life 18, opponent life 20, both Hill Giants reduced to 1/1, and Grizzly Bears removed from the battlefield. A playable Shock keeps a response available while the badge is captured. Prismari Command selected damage and Treasure modes through normal prompts, targeted the opponent for damage and the caster for Treasure, and resolved to opponent life 18 and one Treasure. Both cases assert that obsolete action buttons disappear. Screenshots were inspected after the display corrections.

`provider-local-browser-results.json`, `provider-local-modal-results.json`, and `verification-images/*-local.png` preserve evidence. The reproducible browser harness is `focused-magic-app/assessment/argentum-local-browser.cjs`; it injects only a test-time reconnect helper into the served provider script. Actions, enumeration, state projection, and resolution remain the real native server's. No test helper is added to the production provider.

To repeat, serve `focused-magic-app/` on localhost port 8781; start the verified server JAR on localhost port 8082 with `--game.dev-endpoints.enabled=true --game.ai.enabled=false`; run the harness with Node and the installed web-client Playwright dependency. Enable the scenario endpoint only on the local test server. The adapter's production origin and WebSocket configuration are unchanged.

These checks establish local scenario gameplay and controls. They do not establish exact-deck Constructed admission/start, deployment, live acceptance, generic resource-heavy cost automation, or strong AI paid-life strategy. The overall packet still has seventeen unverified native cards. The separate native gameplay scenarios and full-build records provide the engine evidence.
